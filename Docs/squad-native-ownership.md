# 小队的原生身份与可选模组边界

## 身份不伪装

本模组仍是 **一个实际 Player + 四个原生归属友军 Creature**。队员不是四名联机玩家，也不伪装 `Creature.IsPlayer` 或全局代理 `Creature.Player`。这样才能保留一次共享抽牌、能量、遗物、奖励、结束回合和原生同步语义。

- 真实玩家：共享手牌、能量、球槽、遗物以及共享持续能力。
- 队员：自己的生命、格挡、能力实例、受伤者与行动者身份。
- 明确指定队员的效果保持归属，换位不会移动能力。
- 隐藏玩家入口收到已核实的原生个人能力时，解析至当时前排；集中解析至存活安缇娜。未知外部能力不擅自猜成个人或全队效果。
- 查询、移除应使用 `PowerCmd.Apply<T>` 返回的真实实例及其 `Owner`，或明确队员。**不把对隐藏玩家的所有 `GetPower/HasPower/Remove` 自动改为查询当前前排**；否则换位会让旧效果错误指向另一人。

## 为什么不在换位时改换玩家身份

0.111.0与0.107.1的 `Player.Creature`、`Creature.Player`、`Creature.Monster` 均为构造时赋值的只读引用；`IsPlayer` 由 `Player != null` 推导。`PetOwner` 也不是可重复更换的身份开关。前排变化不是原生玩家生命周期事件。

只伪装 `IsPlayer` 会让“是玩家”与实际Player/Monster引用互相矛盾；反射更换双方引用又不能更新已捕获的伤害目标、能力Owner、战斗订阅和显示节点。若反过来把前排数据搬到固定Player实体，则会破坏四名角色自己的实体/能力身份。因此不把前排当作动态原生玩家，也不承诺这种改造能让第三方模组自动兼容。

前排是小队自己的**当前行为目标**，不是可迁移的Player身份。例如原生对话工厂 `NThoughtBubbleVfx.Create`、`NSpeechBubbleVfx.Create` 仅将隐藏小队入口解析为当前存活前排，再使用原生 `TalkPosition`、气泡渲染与生命周期。明确说话的后排、敌人和普通玩家不重定向。气泡像原版一样在生成时确定锚点，不在显示途中切换说话者。

## 临时属性的原生来源

原生 `TemporaryStrengthPower.BeforeApplied` 先施加Strength，再插入临时能力自身。虎太郎的被动可能嵌套响应前一步，不能复用协同攻击的同一临时能力模型。被动使用独立 `ToraSupportStrength`（来源为其初始遗物），协同攻击仍使用 `SquadTemporaryStrength`；叠层、回合末扣回、图标与提示继续由原生临时力量机制管理。没有吞掉异常、强制把牌丢进弃牌堆或改变出牌循环。

## 2026-10-09 调整

`SquadCombatState.Prepare` 在原生 `Player.PopulateCombatState` 完成时建立四人，早于开场遗物与 `CombatSetUp`。使用宿主初始参与者的实体/宠物注册操作，让原生管理器随后统一登记战斗事件；不是提前调用要求 `IsInProgress` 的中途召唤命令。原来的大蘑菇开场补播已删除，原生进房效果现在直接找到队员。

只有原生第一玩家回合的开场格挡保留例外适用于队员；后续回合清格挡和壁垒等规则仍走原生。`PowerCmd` 实际施加和叠层查找共用同一个功能内目标解析，修复泛型 Apply 返回“未施加的新实例”的问题。

控制台 `godmode` 保留原生命令的开关、下次开战订阅和原生 Strength/Buffer/Regen，仅把明确接收者展开为存活队员。关闭时像原版一样移除这些整组能力，包含普通来源的叠层；不承诺保留开关前的普通力量。光环记录实际能力实例，后续重排不会扣除已经被清掉的旧贡献。

个人能力显示在本人的原生状态栏；共享能力单独复用 `NPowerContainer`，位于队伍上方，不再被能量球/手牌遮住。不增加第五名角色或另一份能力数值。

## 可选模组

忍者杀手的九模组报告仅用于定位风险，不继承 PASS。当前结果见 [验证记录](validation/power-ownership-20261009.md)。

- 海克斯共享出牌/抽牌/能量优先沿用真实 Player，普通个人属性走上述入口。仅限定原版职业的符文不解锁给小队；例如 0.9.7 玩家版濒死狂宴原本仅允许铁甲战士，其单个玩家负血债务也没有复制成四份。
- 东尼可以同载，但本轮**没有**为四人归属、近战和代打设计生成牌映射；没有借用忍杀的组件表替换170张卡池。
- 对外部原始扣血拦截或未知玩法模型，清场预测保守地不启用特写，仍正常攻击与死亡结算。这不是取消外部保命，也不为处决制造假活血量。
- 已查证忍杀 1.0.19 的两个扣血前缀，在没有忍杀角色/相关外部能力参与时不应仅因同载禁用多娜处决。该例外限于精确方法，不按 Harmony owner 整体放行。

不新增硬依赖、全局能力分类平台、额外战斗存档或公共兼容 API。未来遇到只认 `Owner.Creature`、`IsPlayer` 或一个生命条的第三方功能，先确定其玩家可见语义，再在该功能边界适配；不能保证所有未来模组自动兼容。
