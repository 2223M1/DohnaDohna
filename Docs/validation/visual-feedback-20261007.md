# 场景 HUD、荆棘受击与清场处决镜头（2026-10-07）

## 范围与根因

- 场景镜头此前只变换背景和身体。血条/状态栏与意图现在共享镜头平移、缩放和场景震动；角色自身位移/击退仍只影响身体。队列和目标根节点、手牌等屏幕 UI 不动。
- 0.111.0 和 0.107.1 的 `Core/Models/Powers/ThornsPower.cs::BeforeDamageReceived` 都先执行反伤，随后外层 `Core/Commands/CreatureCmd.cs::Damage` 扣血并触发 Hit。0.111.0 的胜利检查随后调用 `AfterCombatEnd`，原先小队的取消令牌立即截断受击。
- 中间候选将镜头直接施加到HUD的Control，完整回归发现原生HP布局会读取这些全球坐标并留下局部偏移。最终改用单次 `MotionCamera` 绘制层，删除该Control变换实现；不改布局坐标。借鉴已查阅的 NinjaSlayer `CombatCinematicCameraLease`，没有移植其全局会话/保护框架。
- 原生 Hit 的非阻塞视觉尾段改由 `RoleVisuals` 的节点生命周期持有：胜利可继续，下一受击、真正死亡与 `_ExitTree` 清理。主攻击仍使用战斗取消令牌；不补伤害、不增加原生多段等待。
- 卡牌数值、存档身份、素材与音频统一 −20 dB 未改动。旧报告关于“演出期间 HUD 固定”的描述不再是场景镜头的现行要求。
- 用户追加并确认：普通攻击仅动作/攻击特效；可靠预判清除全部主要敌人才允许特写、隐藏旁人、黑幕等全屏表现。处决查询原生伤害/格挡/损血/替伤/保命/结束阻止Hook，不执行模拟命令或消费活力；未知玩法内容/实际数值修改、反伤及非单段情况保守拒绝。纯音频/统计/生命周期观察器不会仅因存在就阻止处决。未宣称可预测任意第三方副作用。
- 取景借鉴 NinjaSlayer 的场景约束：逆变换后的视口必须在特写前可见场景内，包含震动最终位移。默认1.35倍轻度特写与原作关键帧结合；角色当前图层、目标边界和32逻辑像素留边会降低倍率，避免把主体裁出画面。无需逐帧读取图片像素。
- 边界例外是人物本身的原作运动，不是镜头：爱丽丝特殊攻击有约710原作单位的后跳，可能超出STS2左侧可见范围。用户明确选择保留原作距离、允许人物短暂出画；不压缩后跳，不为追随人物放宽场景边界。主体同时入镜只在这两项约束允许时满足。
- 同载 NinjaSlayer 的敌人死亡会将身体移入 SubViewport；`BodyChange` 现在只撤销仍属于原父节点的变换，移交后不再操控该身体。
